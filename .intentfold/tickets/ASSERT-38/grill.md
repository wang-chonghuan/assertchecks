## Decided for you

1. **ping token 的 link 是否保留过渡期？** 决定：本单直接移除。依据：工单 Proposed solution 已写明；owner 说"尽量保持简单"；目前唯一调用者是 cap7，同单一起改；客户端每次运行都现下载，旧调用只会得到 404，重新加回成本低。
2. **bugs 不带 check 时打印全部 check 的报告，还是列出 check？** 决定：列出 check（slug、名称、环境），由 agent 选。依据：报告本身按 check（运行、部署版本都是 check 的），只保留一种报告格式；cap7 可按需逐个取。
3. **登录如何不卡住 agent？** 决定：客户端先把待批准的令牌写进本机凭证文件再等待（最多 10 分钟，每 2 秒查一次）；命令被打断也没关系，人批准后下一条命令就能用；再次运行 login 时若已有待批准的请求，就重新打印同一网址继续等，不另起一个。依据：agent 的单条命令有时长上限，10 分钟可能超过。
4. **令牌是否过期？** 决定：批准后不过期，可用 logout 或运维 `client:revoke <email>` 吊销；删除用户时级联删除。依据：与 gh、Vercel 的 CLI 登录一致；内部使用，保持简单。
5. **link 的用例校验范围。** 决定：用例须在该项目任一 check 最新清单里。依据：工单挂在项目的用例上（ASSERT-37 数据模型），ASSERT-37 grill 第 5 条"拼错不能挂到不存在的用例"的意图保留。
6. **登录前未登录网页怎么办？** 决定：`_app` 的跳转和 `/login` 带上同源的 redirect，登录后回到批准页。依据：否则 owner 登录后落在 /p，要再点一次链接，违背"点一下就行"。只接受以单个 `/` 开头的路径，防开放跳转。
7. **网址的 origin。** 决定：服务端按请求的 `x-forwarded-proto` / `x-forwarded-host`（没有则用请求 URL）生成，与浏览器里 Copy bugs 用的 origin 一致。依据：Azure ingress 终止 TLS，请求 URL 可能是 http。
8. **防钓鱼。** 决定：批准页显示验证码和请求时间，写明只在自己刚运行 login 且验证码一致时批准；未批准的请求 10 分钟作废。依据：设备码流程的常见做法；内部工具，不加更多机制。
9. **项目从哪来。** 决定：`--project` 优先，其次当前目录下 `assertchecks/config.json` 的 `project`；都没有就列出账号可见的项目。依据：工单 Proposed solution；NSDK 仓库只读，不能假设它有该字段。
