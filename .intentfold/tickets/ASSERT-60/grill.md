## 代你决定
1. 问题：零失败但未完成是否也使用 passed 文案？
   推荐：否，沿用现有失败计数及未完成状态。
   原因：Product 禁止没有完全执行的运行显示通过；outcome 不由计数单独决定。
   决定：代理按 Charter 和已读 RunHistory / tally 实现，要求 passed outcome 且所有用例通过。
2. 问题：是否仅对 NSDK prod-live 或固定 91 个用例改变文案？
   推荐：不限定，所有确实通过的运行使用现有真实计数。
   原因：标签是共用运行展示行为，不应硬编码项目或展示数据。
   决定：代理按当前 Request 和视图现有数据，统一通过分支。
3. 问题：零用例、无结果、超时或运行中如何避免显示全部通过？
   推荐：必须有非空 tally、ran > 0，且 outcome 为 passed、未超时、passed = ran。
   原因：计数相等可在零用例上成立，单独用 failed = 0 会误导。
   决定：代理按 Product 及已读类型、判断、数据库约束设置上述守卫。
4. 问题：是否更改样式、运行数据或核心判断？
   推荐：不改变，仅切换现有小标签文字。
   原因：现有 passed 数已满足需求；不涉及新 UI 值、数据模型、API、状态机、提示词、迁移或部署依赖。
   决定：代理保留现有样式及其他分支。数据库与登录前提已通过只读查询及已登录页面确认。
