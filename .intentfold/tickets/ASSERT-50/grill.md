# ASSERT-50 Grill

## 你的决定

- **做法。** owner：“你先把这个允许项目自定义报错（或者你就直接把bf的纳入进过滤规则就行了，只处理bf的），这个开发完，再部署。你先开发”。据此 Grill 为 self，Finish 为 auto-deploy。

## 替你决定的（agent，self）

1. **用运维 CLI 声明，不做页面。** 依据：owner 允许“直接把bf的纳入”；CLI 是错误源现有的配置方式。
2. **代码通用、只给 bf 配置。** 依据：owner 偏好“never tied to one client project”（之前的会话），通用声明和写死 BF 的工作量相近。
3. **声明形状为事件名加一个属性等于某值。** 依据：BF 的告警规则就是这个形状；更复杂的条件现在没有需要。
4. **声明的事件不受噪声规则影响。** 依据：浏览器事件可能与 401 请求同一 operation，会被误判为 4xx 噪声；项目明确声明了它是失败。
5. **验收开单用 `--limit 1`。** 依据：只为这个新问题开单，不碰剩余报错（owner 在另一会话处理过滤）。
6. **部署前确认剩余报错的过滤状态。** 依据：部署后定时器会为 bf 其余未过滤的报错开单；owner 正在处理，部署时机以此为准。
