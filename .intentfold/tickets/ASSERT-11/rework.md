## "为啥每次刷新页面，都会导致css先丢失一下？" → "改，然后合并上线"

- **Finding:** frame-by-frame screencasts showed production's first painted frame fully styled; only
  the local dev preview painted one unstyled frame. The cause:
  - Ant prefixes class hashes `css-dev-only-do-not-override-…` in development and `css-…` in
    production.
  - `pnpm dev` and `pnpm build` both wrote the pre-rendered stylesheet to the same
    `src/generated/antd.css`.
  - Running a build while a dev server was running (as the handoff checks did) replaced the dev
    stylesheet with production class names. The dev page then matched none of them until Ant's
    runtime injected styles about 300 ms later.

  A first attempt (stripping Vite's query from the link URL) was based on a wrong reading. It was
  dropped before it was pushed.
- **Change (1 commit):** `scripts/gen-antd-css.tsx` writes `antd.dev.css` outside production and
  `antd.css` in production. `vite.config.ts` resolves the alias `#antd-css` to the file for its
  mode, and `src/routes/__root.tsx` imports `#antd-css?url`.
- **Rechecked:**
  - On the dev preview, the login button is brand blue from the first sampled frame, both before and
    after running `pnpm build` alongside the running dev server.
  - The production build still emits `antd-DWkYQhs5.css`, identical to the live asset, and its
    server paints styled from the first frame.
  - Typecheck, 34 tests and build passed.
  - AC1–AC4 are unaffected: no page content changed.
- **Charter drift to report:** `charter/engineering.md` (Tools → Architecture and generation) still
  says only "`src/generated/antd.css` is generated by `pnpm antd-css` and git-ignored". It now also
  generates `src/generated/antd.dev.css` for development. The owner decides the wording; the agent
  does not edit the charter.
