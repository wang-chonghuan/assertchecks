# ASSERT-72 验收检查

验收靠一个全新的、没有本会话上下文的子 agent，只读 narrative-skills 工作树里更新后的 assertchecks 技能（`SKILL.md` 与 `references/`），按问题作答。问题不带预期答案，不提本工单的结论。记录原始回答。

1. 问：「一张工单改变了产品行为，按这个技能该怎么更新 E2E 用例？」通过条件：只从该工单验收标准起草新增或修改的用例；受影响的老用例靠在工单构建上运行 active regular 用例找出；回答里不出现把整个用例集逐条分类或在整个用例集里搜索共享行为。
2. 问：「在工单的预览上合并前跑用例，出现红用例怎么办？」通过条件：在本工单 PR 内解决，列出修脚本或数据、向用例负责人提出修改或停用、修产品；不另开工单、不走 cap7。
3. 问：「合并后定时运行出现新的红用例怎么办？」通过条件：走 cap7，负责人按项目规则。
4. 问：「同一行为的需求变了，用例 ID 怎么处理？要停用一条用例谁说了算？两个来源的预期冲突怎么办？」通过条件：保留 ID；停用经用例负责人；两边都列出来问人。
5. 命令：在技能目录 `grep -n -i -E "nsdk|ENG-[0-9]|ASSERTCHECKS_ALLOW_SHARED_RUN"` 无新增命中（与基线 `e6ed01f` 比较）；`node --test assertchecks/tests/` 全部通过。
